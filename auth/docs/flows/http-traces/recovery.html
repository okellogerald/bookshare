Understanding the recovery JSON
"active": "code"
The active recovery strategy. Kratos supports multiple strategies; BookShare uses code (a 6-digit code sent to the user's email). This is configured in kratos.yml.
group: "code"
All recovery-specific nodes use this group. Unlike registration (which has "default", "profile", "password"), recovery only has "default" (CSRF) and "code" (the recovery method).
"email" field
The user's email address input. Kratos uses this to look up the identity. If no identity exists with this email, Kratos still behaves identically (to prevent email enumeration).
"method": "submit"
The submit button with value: "code". Sends method=code to tell Kratos to use the code recovery strategy.
Note
At this point there is no session and no privileged access. Recovery is in the "who are you?" phase.

Note — Critical transition: recovery to settings
This is the most important step in the recovery flow. Three major things happen:

1. Privileged session created. Kratos creates a session with elevated privileges. This is not a normal login session — it has a short privilege window (15 minutes by default) that allows the user to change their password without re-entering their current one.

2. New flow type. The redirect points to /settings with a new flow ID. The recovery flow (74124c0b...) is consumed and replaced by a settings flow (b871d432...). This is a different flow type entirely.

3. No password written yet. The recovery code only proves identity ownership — it does not set a new password. The actual password change happens in the settings flow (Stage 6-7).
Warning
The recovery code is single-use. Once submitted successfully, it cannot be reused. If the user navigates away before setting a new password, the privileged session eventually expires (15 minutes) and they must start recovery again.

Understanding the settings flow in recovery context
"request_url" points to recovery
This confirms this settings flow was created by the recovery process. Normal settings flows have a /settings request_url.
group: "profile" nodes
Kratos includes the full profile (email, name, gender) with pre-filled values. BookShare ignores these entirely in recovery mode — the user is here to reset their password, not edit their profile.
group: "password"
The password input field and method=password submit. This is the only group BookShare renders. No "current password" field is required because the privileged session from the recovery code grants access.
"messages" with ID 1060001
Kratos' built-in recovery success message indicating the 15-minute privilege window.
Note — Why recovery has its own settings model
Kratos returns a generic settings flow with both profile and password groups. BookShare must filter this down to password-only to create the recovery password reset experience.
